title: Privacy and security
description: Understand the boundaries before you share.
---

## Local by default

Mayfly streams only explicitly selected files from your computer to
a reachable browser on your trusted local network. No account or cloud relay is
required for that default workflow. Real local transfers are implemented in the
development build; public-release and device acceptance remain pending.

The public Mayfly website serves product information, documentation, and eventually
installers. It does not host or relay the files you choose to share.

## HTTP is unencrypted

A local HTTP connection does not encrypt the transferred contents or the token in
the URL. Use trusted networks. Avoid public Wi-Fi, untrusted guest networks, and
router port forwarding.

## The link grants access

A share token is a temporary bearer credential. Anyone who gets the URL or its QR
code and can reach the service can use it while the share is valid. A hard-to-guess
token is not the same as identifying a trusted recipient.

Use short lifetimes, deliberate download limits, and manual revocation. Do not
include live URLs, codes, private filenames, or absolute paths in bug reports.

## No permanent permission

Active shares and tokens stay in memory. Full application restart invalidates
earlier links; settings and link profiles are saved locally. Stopping a share or
quitting cuts off its running downloads. Expiration blocks new requests while
already-started downloads may finish.

## One link, one audience

Everyone with a share's link can access its current files, including files added
later. A direct file link contains the same share token; it does not isolate that
file from the rest of the share. Use separate links for different recipients.

Creating an empty link prepares access for files you add later. A title is visible
to recipients, so keep private information out of names and screenshots. Local
downloads provide access through the link, without a recipient login or a share
password. Password protection is planned separately.

## Remote tools change the boundary

Public tunnels expose the service outside your LAN and can introduce provider
logging and TLS termination. Private Tailscale access and public Funnel are different
models. Read [Remote sharing](../remote-sharing/) before considering either.

## Reporting a vulnerability

Use the repository's private vulnerability-reporting option when available.
If it is unavailable, ask the owner for a private channel without posting exploit
details. Source access and the reporting route are subject to the project's current
private-repository policy.
