## Browser first

The built-in **Share page** profile opens the browser download page. Every share
also has a direct link per file and a ZIP link for downloading its files together.
See [Share files](../sharing/) for when to use each.

Custom link profiles turn the share-page URL into a link understood by a compatible
app. Create, edit, or delete them in **Settings → Link profiles**. Profiles and the
default choice are saved locally with your settings.

## Create a profile

Choose **New profile**, then enter a name and a URL template. For example:

```text
Name: My import app
Template: myapp://import?url={encodedUrl}&name={encodedFilename}
```

The editor previews the resolved URL with example data and validates the template.
`myapp` is an example scheme; use the scheme and import format documented by your
target app. That app must be installed on the receiving device. A real handoff to
a compatible mobile app still needs device-specific verification.

## Available placeholders

| Placeholder | Value |
| --- | --- |
| `{url}` | Full share page URL |
| `{encodedUrl}` | That URL encoded as a single URI component |
| `{filename}` | Share display name: title, filename, or file count |
| `{encodedFilename}` | That display name encoded as a single URI component |
| `{token}` | Share token |

Prefer encoded values inside query parameters. Templates resolve once; braces in
inserted values are not interpreted again. Rust rejects unknown placeholders,
malformed braces, control characters, and unsafe schemes such as `javascript:`,
`data:`, and `file:`.

## Choose what the QR opens

Star a profile to make it the QR default. In the share details, use
**What the QR code opens** to switch between the share page and an app profile.
The displayed code, copied QR image, and QR save action use the selected target.
A file's own QR button switches to that file's direct download.

The inspector's **Copy link** action copies its displayed target; the share row's
copy action still gives you the share-page URL. Deleting the
default custom profile falls back to **Share page**. FileHop creates links without
running templates, installing apps, or registering their schemes.

A profile does not configure routing or make a local address public. See
[Remote sharing](../remote-sharing/) for that separate, unverified topic.
