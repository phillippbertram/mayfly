## Browser first

Every share already has the links most people need: the share page (what the QR
code opens), a ZIP of all files, and a direct download link for each file. See
[Share files](../sharing/) for when to use which.

Custom profiles add links for apps: a profile describes how a compatible
application expects to receive a share URL. Each profile adds **Copy link for …**
to a share's menu and can be what the QR code opens. Profiles don't change what a
share's own links open, and they don't install an application, register a scheme,
or create network connectivity. FileHop only builds and copies these links; it
never opens them itself.

## Create a profile

Open **Settings → Link profiles**, choose **New profile**, and enter a name and
template. A live preview shows the resulting link. For example:

```text
Name: My import app
Template: myapp://import?url={encodedUrl}&name={encodedFilename}
```

`myapp` is an example scheme, not a claim about an installed application. Use the
scheme and import format documented by your actual target app.

## Available placeholders

| Placeholder | Value |
| --- | --- |
| `{url}` | Full share page URL |
| `{encodedUrl}` | That URL encoded as a single URI component |
| `{filename}` | The share's title, its file name, or "N files" |
| `{encodedFilename}` | That name encoded as a single URI component |
| `{token}` | Share token |

Prefer encoded values inside query parameters. Templates are resolved once, so
braces in a filename never become a second round of placeholders. FileHop refuses
unknown placeholders, unmatched braces, line breaks, templates without a scheme,
and schemes such as `javascript:`, `data:`, or `file:`. Profiles are saved with
your settings, up to 20 of them.

## Choose what the QR code opens

Mark a profile with the star to make it the QR default. In a share's details,
**QR opens** switches between the share page and your profiles for that share; the
QR code, the link field, copying, and saving the QR as PNG all use the shown
choice. Deleting the default falls back to the share page.

A custom scheme such as `myapp://` only works on a device where a compatible app
is installed. Opening such links on real phones hasn't been tested with specific
apps yet; check with your target app.

A custom profile does not turn a local address into a public one.
See [Remote sharing](../remote-sharing/) for that separate topic.
