## Sharing workflow

FileHop's desktop development build serves real files over your local network.
There are no published installers yet, and the flow has been checked on a Mac
with a browser on the same computer, not yet on a phone or a second device.

1. Connect your computer and the receiving device to the same trusted Wi-Fi or local network.
2. Open FileHop and confirm that the server reports a usable network address.
3. Drop one or more files into the window, or select **Choose files**.
4. Choose how long the link works and how often each file may be downloaded, then select **Share**.
5. Scan the QR code with a phone's camera, or open the link in any browser on another computer.
6. Check the files on the page, then select **Download**, or **Download all** for a ZIP.

Files stream from their original location. Nothing is uploaded to a cloud service,
and FileHop doesn't copy the files; a ZIP is assembled while it downloads.

## One link, three ways in

Every share has:

- **The share link**, which the QR code opens: a page showing the file, or a list
  of files with **Download all**. Opening it never counts as a download.
- **A direct link for each file**, copied from the file list in the share details.
  It starts the download right away.
- **A ZIP link** for shares with several files, from **Copy ZIP link**.

Chat apps fetch links to show previews. For a direct or ZIP link, that fetch is a
download, so with a download limit, prefer the share link.

Several files you share together go behind one link by default. To give each file
its own link, for example for different people, turn on **Give each file its own
link** before sharing. A download limit applies to each file: a limit of 1 lets
someone fetch every file once, either one by one or as the ZIP.

## Add and remove files later

While a share is active, use **Add files…** in the share details or press **A**, or
drag files onto the share in the list or onto its details. While you drag, FileHop
outlines the target and shows **Add to “…”**; dropping anywhere else shows **New link**
and creates a new share. Remove a file with the
button next to it. The share link and its QR code stay the same, so someone can keep
the page open on another computer and reload it to see new files.

Everyone with the link sees whatever the share currently holds, including files
you add later. Removing a file stops its running downloads, and its old direct link
says it was removed.

To prepare a link before you know the files, choose **New empty link** (or press
**Cmd/Ctrl+N**), open its link or QR code on the other device, and add files as they
come up.

## Name a link

Give a share a title, such as "Photos for Alex", with the pencil next to its name in
the share details or by pressing **T**. The title shows in your list and as the
heading of the page recipients open. Clear it to go back to the file name.

## A QR code for one file

The QR code normally opens the share page. To let someone scan a single file's direct
download instead, select the QR button next to that file in the share details;
**Show share QR** switches back.

## Before choosing files

Share readable individual files. Folders are skipped; directory sharing is outside the MVP.
Keep the computer awake and FileHop running. FileHop keeps serving the file you
selected even if its name or location changes. If the file's contents change size,
the page reports it as unavailable instead of sending a mismatched file.

The browser-only preview (`pnpm dev:web`) adds sample metadata only. A share shown
in that preview is not a working download.

## Keep the right address

With multiple network interfaces, choose the address the other device can reach
in **Settings → Network**. A guest Wi-Fi network, VPN, or client-isolation setting can
prevent access even when both devices appear to use the same router.

A link looks like this:

```text
http://192.168.1.20:8765/s/EXAMPLE_TOKEN
```

This is an example, not a live share.

## Stop when you are done

Use **Stop sharing** to revoke a share before its deadline; running downloads stop too.
Expiration and download limits block new downloads. See [Expiration and limits](../expiration/)
for the policy and the difference between starting a download and saving a file.
