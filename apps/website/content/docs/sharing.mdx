## Sharing workflow

FileHop's desktop development build serves real files over your local network.
There are no published installers yet, and the flow has been checked on a Mac
with a browser on the same computer, not yet on a phone or a second device.

1. Connect your computer and the receiving device to the same trusted Wi-Fi or local network.
2. Open FileHop and confirm that the server reports a usable network address.
3. Drop one or more files into the window, or select **Choose files**.
4. With several files, choose **One link for all** or separate links, then select **Share**.
5. Scan the QR code with a phone's camera, or open the link in any browser on another computer.
6. Check the files on the page, then select **Download**, or **Download all** for a ZIP.

To skip the page, choose **Direct download** under **Link** before sharing: the
link then starts the download, or the ZIP for several files, right away. See
[Link profiles](../link-profiles/) for when the page is the better choice.

Files stream from their original location. Nothing is uploaded to a cloud service,
and FileHop doesn't copy the files; a ZIP is assembled while it downloads.

## One link for several files

When you share several files with one link, the page lists every file with its
own download button, plus **Download all** as a ZIP. A download limit applies to
each file: a limit of 1 lets someone fetch every file once, either one by one or
as the ZIP. Once any file has reached its limit, the ZIP is no longer offered.

## Keep a link open for more files

Choose **Keep open for more** under **Links** to create a link you can keep
filling. In the share details, use **Add files…** or drop files onto the file list
to add them, and the remove button next to a file to take it out again. The link
and its QR code stay the same, so someone can keep the page open on another
computer and reload it to see new files.

Everyone with the link sees whatever the link currently holds, including files
you add later. Removing a file stops its running downloads, and its old download
link says it was removed.

## Before choosing files

Share readable individual files. Folders are skipped; directory sharing is outside the MVP.
Keep the computer awake and FileHop running. FileHop keeps serving the file you
selected even if its name or location changes. If the file's contents change size,
the page reports it as unavailable instead of sending a mismatched file.

The browser-only preview (`pnpm dev:web`) adds sample metadata only. A share shown
in that preview is not a working download.

## Keep the right address

With multiple network interfaces, choose the address the other device can reach
in **Settings → Network**. A guest Wi-Fi network, VPN, or client-isolation setting can
prevent access even when both devices appear to use the same router.

A link looks like this:

```text
http://192.168.1.20:8765/s/EXAMPLE_TOKEN
```

This is an example, not a live share.

## Stop when you are done

Use **Stop sharing** to revoke a share before its deadline; running downloads stop too.
Expiration and download limits block new downloads. See [Expiration and limits](../expiration/)
for the policy and the difference between starting a download and saving a file.
